# Contratos: o saldo precisa explicar sua história

Esta página reúne os contratos que a prática compara. Você aprenderá a distinguir o fato registrado, a projeção para consulta e a recuperação local de uma transação incompleta. Os valores descritos pertencem a um laboratório local com entradas fictícias.

Para continuar o mesmo problema, [volte à jornada](/jornadas/ledger-projection/), [entenda o mecanismo](/explicacoes/casos/ledger-projection/), [execute o tutorial](/tutoriais/casos/ledger-projection/) ou [consulte o guia da tarefa](/guias/casos/ledger-projection/).

## Entradas e ambiente

Eventos credit/1000, credit/100 e debit/200; snapshot no evento 2; tabela SQLite temporária com 100.000 centavos.

| Contrato | Valor do caso |
| --- | --- |
| Identidade do caso | `ledger-projection`. |
| Símbolos a consultar | `ledger_projection / replay-events / projection-checkpoint / durable-transaction`. |
| Comando completo | `python3 labs/architecture/financial.py ledger-projection`. |
| Dados e efeito externo | As entradas são sintéticas. A prática conserva os efeitos em memória ou em um arquivo temporário local. |
| Versões da execução registrada | Python `3.14.8` e Node `v26.8.1`. |
| Horário e escopo do recibo | `2026-10-15T01:35:30.851025+00:00`, no laboratório local. |

O tutorial explica a preparação e como reiniciar. O comando acima é uma consulta rápida para quem já preparou o ambiente.

## Fonte do modelo financeiro

Este é um caso financeiro hipotético com participantes e dados fictícios. Uma corretora de maior porte, do setor em que atua a XP, é apenas o contexto de negócio. O texto não descreve um incidente nem uma arquitetura interna real da XP. A busca delimitada localizou candidatos da nossa stack, mas não estabeleceu um caso histórico completo para todos os conceitos desta família.

A função `ledger_projection` está em `labs/architecture/financial.py`. O artefato `tasks/FBI-4991-arquitetura-nextra/execution/learning/searches/ledger-projection.json` conserva o alcance da busca por um caso interno. O modelo serve para comparar uma garantia com uma falha delimitada; ele não implementa integralmente todas as tecnologias relacionadas.

## Resultados que o contrato compara

O replay e a projeção chegam a R$ 900. O snapshot de R$ 1.100 mais o débito de R$ 200 chega ao mesmo saldo. O SQLite executa uma transação em journal_mode=wal e conserva 100.000 centavos após rollback.

## Garantia, parâmetros e limites

A projeção consome os fatos faltantes. Uma transação local pode fazer rollback. Um snapshot da posição 2 reduz o replay ao evento seguinte. Os eventos são fictícios. O WAL medido é do SQLite; ele não prova recovery PostgreSQL. Uma outbox, um log de auditoria ou uma projeção sozinha não transforma qualquer sistema em Event Sourcing.

Uma repetição usa a mesma entrada conhecida. Nos modelos financeiros, `--probe <nome>` restringe a comparação ao probe escolhido. Um nome desconhecido encerra o programa; o argumento não cria um novo cenário. Nos recortes históricos, os parâmetros e doubles estão nos runners de cada pasta.
