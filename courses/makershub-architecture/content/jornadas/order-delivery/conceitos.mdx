# Conceitos: uma ordem repetida cobra de novo

Este mapa conecta os conceitos ao mesmo problema. Ana envia a ordem fictícia ORDER-1 de R$ 100. A resposta se perde e o cliente a repete. ORDER-2 acrescenta R$ 50. O desenho anterior registra R$ 100 + R$ 100 + R$ 50 = R$ 250. A ordem repetida deveria conservar o mesmo efeito, totalizando R$ 150.

Comece pela [jornada](/jornadas/order-delivery/), execute o [tutorial](/tutoriais/casos/order-delivery/) e use a [referência](/referencia/casos/order-delivery/) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/guias/casos/order-delivery/).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

<span id="at-least-once-delivery" />

## At-Least-Once Delivery

O transporte pode reentregar uma mensagem enquanto busca sua confirmação, portanto o consumidor precisa tolerar repetição.

No caso desta família, faça a seguinte observação: Entregue EVENT-1 e perca somente sua confirmação. Repita até receber a confirmação e conte as duas entregas da mesma identidade.

```sh
python3 labs/architecture/financial.py order-delivery --probe at-least-once-ack-retry
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `at-least-once-ack-retry`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "acknowledged": false,
    "attempts": 1
  },
  "after": {
    "acknowledged": true,
    "attempts": 2,
    "deliveries": 2,
    "unique_event_ids": 1
  }
}
```

O vínculo é uma comparação executável de princípio. Only this bounded acknowledgement-loss schedule is modeled; an exactly-once effect still needs the recipient transaction or idempotency mechanism.

A [explicação do capítulo](/explicacoes/reliable-integration/) amplia a decisão, e a [entrada de referência](/referencia/catalogo/02-sistemas-distribuidos-e-consistencia/#g02-e018) descreve o conceito para consulta. A [jornada do caso](/jornadas/order-delivery/) permite continuar com o mesmo problema.

## At-Most-Once Delivery

O mecanismo não reentrega a ocorrência depois do envio, podendo perdê-la.

No caso desta família, faça a seguinte observação: Perdida a confirmação, compare repetir sem deduplicação com fazer somente uma tentativa. Depois perca a própria entrega e observe que nenhuma tentativa adicional a recupera.

```sh
python3 labs/architecture/financial.py order-delivery --probe at-most-once-loss
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `at-most-once-loss`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "retry_without_dedup_effects": 2
  },
  "after": {
    "ack_lost_effects_without_retry": 1,
    "delivery_lost_effects_without_retry": 0,
    "maximum_attempts": 1
  }
}
```

O vínculo é uma comparação executável de princípio. This is a sender-attempt model, not a broker delivery guarantee or proof of the external effect.

## CDC Migration

A migração copia um estado inicial e acompanha mudanças registradas pela origem até a troca.

No caso desta família, faça a seguinte observação: Atualize a origem dentro de uma transação que faz rollback e depois numa que faz commit. Leia o feed capturado e aplique o valor no destino da migração.

```sh

```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `cdc-committed-change`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "independent_target_cents_after_second_write_failure": 100000
  },
  "after": {
    "captured_committed_changes": 1,
    "rolled_back_changes": 0,
    "target_cents": 110000
  }
```

O vínculo é uma comparação executável de princípio. Trigger-based CDC in SQLite is not WAL decoding, Debezium or a cross-database atomic transaction; cutover still requires reconciliation.
