# Conceitos: a posição rápida pertence ao outro recorte

<CaseNavigation caseId="cache-policy" current="concepts" />

Este mapa conecta os conceitos ao mesmo problema. Ana consulta a posição fictícia do tenant A. Depois, Bruno consulta a posição do tenant B. Uma chave que contém apenas position entrega a Bruno o valor de Ana. O mesmo caso permite observar o que acontece quando um valor vence, quando o cache local envelhece e quando uma escrita em memória é perdida numa queda.

Comece pela [jornada](/jornadas/cache-policy/), execute o [tutorial](/jornadas/cache-policy/#tutorial) e use a [referência](/jornadas/cache-policy/#reference) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/jornadas/cache-policy/#guide).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

## Cache Aside

A aplicação lê o cache e, na falta, consulta a origem e grava o resultado.

No caso desta família, faça a seguinte observação: Faça três leituras da posição. Observe o primeiro miss carregar e preencher a chave; os dois hits seguintes conservam uma única consulta à fonte.

```sh
python3 labs/architecture/financial.py cache-policy --probe cache-aside
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `cache-aside`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "source_calls": 3,
    "values": [
      1000,
      1000,
      1000
    ],
    "cache_populated": true
  },
  "after": {
    "source_calls": 1,
    "values": [
      1000,
      1000,
      1000
    ],
    "cache_populated": true
  }
}
```

O vínculo é um mecanismo local executado. Os níveis são dicionários locais. Não se executou Redis, cache distribuído, política de eviction ou medição de desempenho. O caso histórico de single-flight oferece uma execução distinta do cancelamento e da renovação.

O código desta observação está em `labs/architecture/models_architecture.py`. O identificador do probe é `distributed-cache-owner`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "independent_worker_cache_source_calls": 2

      1000
```

O vínculo é uma comparação executável de princípio. The owners are local dictionaries; the experiment isolates shared-owner cache semantics without claiming a networked cache product or cross-machine durability.
