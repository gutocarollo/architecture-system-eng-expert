# Conceitos: os escritórios deixam de conversar

Este mapa conecta os conceitos ao mesmo problema. Uma corretora hipotética divide o serviço em três participantes: A, B e C. Uma falha de comunicação deixa A e B juntos e C sozinho. Se cada grupo se declarar autorizado a gravar, duas decisões incompatíveis podem aparecer. A prática permite somente ao grupo que reúne dois dos três participantes autorizar a escrita.

Comece pela [jornada](/jornadas/consensus/), execute o [tutorial](/tutoriais/casos/consensus/) e use a [referência](/referencia/casos/consensus/) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/guias/casos/consensus/).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

## Active/Active

Active/active significa que participantes atendem trabalho ao mesmo tempo; o contrato especifica se são leituras ou escritas.

No caso desta família, faça a seguinte observação: Aceite um crédito distinto em A e B. Compare a última substituição absoluta de saldo com a reconciliação das identidades dos dois créditos.

```sh
python3 labs/architecture/financial.py consensus --probe multi-writer-reconcile
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `multi-writer-reconcile`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "last_absolute_balance_wins": 1050,
    "lost_credit": 100
  },
  "after": {
    "sites_accepting_writes": 2,
    "merged_balance": 1150,
    "unique_credits": 2
  }
}
```

O vínculo é uma comparação executável de princípio. This merge is valid only for the declared independent credits; noncommutative debits and invariants need a business conflict policy.

## Asynchronous Replication

No caso desta família, faça a seguinte observação: Atualize o primário para a versão 2, observe a réplica na versão 1 e aplique a atualização para que ela também chegue à versão 2.

```sh
python3 labs/architecture/financial.py consensus --probe replica-lag
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `replica-lag`.

```json
    "primary_version": 2
  },
  "after": {
    "replica_version": 2,
```

No caso desta família, faça a seguinte observação: Mantenha a réplica na versão 1 enquanto o primário está na 2. Confira que a confirmação sincronizada espera a aplicação e que a leitura dessa réplica após a confirmação vê a versão 2.

```sh
python3 labs/architecture/financial.py consensus --probe synchronous-replica-ack
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `synchronous-replica-ack`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "writer_ack_before_replica_applied": true

    "ack_after_replica_applied": true,
```

O vínculo é uma comparação executável de princípio. This bounded primary/replica schedule does not alone prove linearizability, all replica routing or consistency under partitions.

## Three-Phase Commit / 3PC

O 3PC acrescenta pré-commit entre votação e decisão final, dentro de um modelo de comunicação e falhas.

No caso desta família, faça a seguinte observação: Faça os dois participantes reconhecerem canCommit e preCommit. Compare a decisão no modelo síncrono declarado com o caso em que uma partição ainda é possível.

```sh
python3 labs/architecture/financial.py consensus --probe three-phase-precommit
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `three-phase-precommit`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "two_phase_prepared_timeout": "wait_for_coordinator"
  },
  "after": {
    "phases_before_timeout": [
      "canCommit",
      "preCommit"

    "all_precommitted": true,
    "decision_under_synchronous_no_partition_assumption": "commit",

```

O vínculo é uma comparação executável de princípio. This is not a partition-tolerant atomic commit implementation; the autonomous commit decision is not generalized outside those assumptions.

## Two-Phase Commit / 2PC

No caso desta família, faça a seguinte observação: Interrompa a comunicação após prepare e examine por que um participante não pode inventar commit ao vencer um tempo local.

```sh
python3 labs/architecture/financial.py consensus --probe prepared-participant
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `prepared-participant`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "prepared_then_timeout": "commit_guessed"
  },
  "after": {
    "prepared_then_timeout": "wait_for_decision"
  }
}
```

O vínculo é uma comparação executável de princípio. O probe exercita um requisito ou um contraexemplo relacionado a Two-Phase Commit / 2PC; não implementa o padrão completo. A prática mostra requisitos e contraexemplos, em um modelo finito. Ela não implementa Raft, Paxos, 2PC ou 3PC completos, não prova linearizabilidade e não cobre todas as falhas assíncronas.
