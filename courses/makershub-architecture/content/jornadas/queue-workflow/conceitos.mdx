# Conceitos: a fila cresce durante uma dependência lenta

Este mapa conecta os conceitos ao mesmo problema. Ana importa 120 solicitações fictícias em uma corretora. O consumidor só consegue manter 20 na fila escolhida para a prática. Ao mesmo tempo, uma mensagem inválida falha sempre. O desenho anterior cresce sem limite e repete a mensagem inválida; a versão protegida limita a entrada e separa a mensagem que já gastou três tentativas.

Comece pela [jornada](/jornadas/queue-workflow/), execute o [tutorial](/tutoriais/casos/queue-workflow/) e use a [referência](/referencia/casos/queue-workflow/) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/guias/casos/queue-workflow/).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

No caso desta família, faça a seguinte observação: Ofereça três chamadas no segundo 0 e uma no segundo 1. Com limite de duas por segundo, confira três admissões e uma recusa.

```sh
python3 labs/architecture/financial.py queue-workflow --probe rate-window
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `rate-window`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "accepted": 4,
    "rejected": 0
  },
  "after": {
    "accepted": 3,
    "rejected": 1,
    "per_second_limit": 2
  }
}
```

O vínculo é uma comparação executável de princípio. O probe exercita um requisito ou um contraexemplo relacionado a Throttling; não implementa o padrão completo. A fila está em memória. A DLQ, o circuito e as dependências são modelos limitados, sem broker, Airflow, durable workflow, promessa de exactly-once ou temporização de rede.

## Workflow Engine

Um motor de workflow interpreta um contrato de passos e administra sua execução, dependências e progresso.

No caso desta família, faça a seguinte observação: Interrompa depois de persistir credited, feche a conexão e reabra o arquivo de progresso. Confira que a retomada executa a notificação e não repete o crédito já registrado.

```sh
python3 labs/architecture/financial.py queue-workflow --probe durable-workflow-resume
```

O código desta observação está em `labs/architecture/models_workflow.py`. O identificador do probe é `durable-workflow-resume`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "restart_from_beginning_credit_attempts": 2
  },
  "after": {
    "phase_loaded_after_reopen": "credited",
    "final_phase": "complete",
    "effect_keys": [
      "credit:ORDER-1",
      "notify:ORDER-1"
    ],
    "credit_effects": 1
  }
}
```

O vínculo é uma comparação executável de princípio. The local effects and checkpoints share SQLite transactions. External activity retries, timers, worker leasing and a full durable-workflow framework are not implemented.

A [explicação do capítulo](/explicacoes/workflow/) amplia a decisão, e a [entrada de referência](/referencia/catalogo/16-workflow-e-processamento/) descreve o conceito para consulta. A [jornada do caso](/jornadas/queue-workflow/) permite continuar com o mesmo problema.
