# Conceitos: a consulta cresce e a soma muda de significado

<CaseNavigation caseId="storage-partitions" current="concepts" />

Este mapa conecta os conceitos ao mesmo problema. A corretora hipotética cresce e divide as posições por chave. Ana procura a posição 7. Uma regra de roteamento permite buscar uma das três partições, enquanto uma junção com registros filhos pode multiplicar os valores financeiros. A prática usa doze posições e duas contas para tornar esses efeitos visíveis.

Comece pela [jornada](/jornadas/storage-partitions/), execute o [tutorial](/jornadas/storage-partitions/#tutorial) e use a [referência](/jornadas/storage-partitions/#reference) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/jornadas/storage-partitions/#guide).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

## Consistent Hashing

O mecanismo associa chaves a posições e reduz remapeamento quando participantes mudam.

No caso desta família, faça a seguinte observação: Adicione o nó D ao anel com pontos virtuais e conte as chaves cujo próximo dono muda. Compare com o remapeamento do módulo de três para quatro shards.

```sh
python3 labs/architecture/financial.py storage-partitions --probe consistent-ring
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `consistent-ring`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "modulo_moved_keys": 76,
    "keys": 100
  },
  "after": {
    "ring_moved_keys": 24,
    "keys": 100,
    "existing_owner_kept": 76
  }
}
```

O vínculo é uma comparação executável de princípio. O probe exercita um requisito ou um contraexemplo relacionado a Consistent Hashing; não implementa o padrão completo. O roteamento usa módulo, não consistent hashing. O remapeamento quantifica sua fragilidade ao acrescentar um shard. O laboratório não implementa replicação geográfica, consenso de réplicas ou uma topologia PostgreSQL.

A [explicação do capítulo](/explicacoes/data-distribution/) amplia a decisão, e a [entrada de referência](/referencia/catalogo/05-banco-de-dados-e-armazenamento/#g05-e018) descreve o conceito para consulta. A [jornada do caso](/jornadas/storage-partitions/) permite continuar com o mesmo problema.

## Write Amplification Control

Controlar amplificação de escrita significa gerir bytes fisicamente escritos em relação à alteração lógica.

No caso desta família, faça a seguinte observação: Agrupe dez substituições do mesmo snapshot de posição antes de confirmar o lote e grave o último valor uma vez. Compare as escritas físicas necessárias.

```sh
python3 labs/architecture/financial.py storage-partitions --probe coalesced-snapshot-writes
```

O código desta observação está em `labs/architecture/models_distribution.py`. O identificador do probe é `coalesced-snapshot-writes`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "physical_snapshot_writes": 10
  },
  "after": {
    "physical_batch_writes": 1,
    "latest_snapshot": 1009,
    "updates_in_acknowledged_batch": 10
  }
}
```

O vínculo é uma comparação executável de princípio. This applies to replaceable snapshots, not ten independent ledger facts. No per-update durability is promised before the batch flush.
