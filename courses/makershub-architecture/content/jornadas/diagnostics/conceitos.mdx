# Conceitos: o processo responde, mas a ordem não terminou

<CaseNavigation caseId="diagnostics" current="concepts" />

Este mapa conecta os conceitos ao mesmo problema. A ordem fictícia ORDER-1 passa por uma requisição que falha no provedor e por uma segunda tentativa. Ana vê um health endpoint verde e ainda não sabe onde o pedido parou. A prática reúne os dois request IDs sob um operation ID e separa tempo, erro e resultado do caminho de negócio.

Comece pela [jornada](/jornadas/diagnostics/), execute o [tutorial](/jornadas/diagnostics/#tutorial) e use a [referência](/jornadas/diagnostics/#reference) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/jornadas/diagnostics/#guide).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

## Centralized Logging

Reúne logs de diferentes componentes para consulta com retenção e acesso definidos.

No caso desta família, faça a seguinte observação: Reúna REQUEST-1 e REQUEST-2 sob ORDER-1 e confira três spans sem confundir tentativa e operação.

```sh
python3 labs/architecture/financial.py diagnostics --probe correlate-retries
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `correlate-retries`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "trace_one_request_spans": 2
  },
  "after": {
    "operation_spans": 3,
    "requests": 2
  }
}
```

O vínculo é uma comparação executável de princípio. O probe exercita um requisito ou um contraexemplo relacionado a Centralized Logging; não implementa o padrão completo. O conjunto é sintético e pequeno. Ele não prova instrumentação OpenTelemetry real, percentil, SLO, causa de incidente ou capacidade de produção.

A [explicação do capítulo](/explicacoes/observability/) amplia a decisão, e a [entrada de referência](/referencia/catalogo/15-observabilidade/#g15-e002) descreve o conceito para consulta. A [jornada do caso](/jornadas/diagnostics/) permite continuar com o mesmo problema.

## Distributed Tracing

Relaciona etapas causais por spans e contexto propagado.

No caso desta família, faça a seguinte observação: Execute o SDK OpenTelemetry fixado, injete e extraia traceparent entre gateway e provider e exporte para memória. Confira o mesmo trace, o parent span e o erro, sem confundir dois spans com duas requisições.

```sh
python3 labs/architecture/financial.py diagnostics --probe opentelemetry-sdk-export
```

O código desta observação está em `labs/architecture/models_ops.py`. O identificador do probe é `opentelemetry-sdk-export`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "exported_spans": 0,
    "traceparent_propagated": false
  },
  "after": {
    "exported_spans": 2,
    "failed_spans": 1,
    "parent_matches": true,
    "request_ids": 1,
    "same_trace": true,
    "span_names": [
      "gateway",
      "provider"
    ],
    "traceparent_propagated": true
  }
}
```

O vínculo é uma comparação executável de princípio. The exporter is in memory with SDK 1.45.1. There is no collector, network service or claim of production instrumentation.
