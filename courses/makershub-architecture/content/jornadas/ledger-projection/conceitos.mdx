# Conceitos: o saldo precisa explicar sua história

Este mapa conecta os conceitos ao mesmo problema. Uma posição fictícia recebe crédito de R$ 1.000, crédito de R$ 100 e débito de R$ 200. Um saldo mutável sem histórico pode perder uma alteração. A trilha de eventos permite refazer a conta: 1.000 + 100 − 200 = R$ 900, inclusive quando o modelo de consulta ainda não consumiu os dois últimos eventos.

Comece pela [jornada](/jornadas/ledger-projection/), execute o [tutorial](/tutoriais/casos/ledger-projection/) e use a [referência](/referencia/casos/ledger-projection/) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/guias/casos/ledger-projection/).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

## Append-Only Log

Um append-only log acrescenta registros na ordem definida segundo seu contrato de retenção e correção.

No caso desta família, faça a seguinte observação: Reproduza os fatos 1.000, +100 e −200 e conserve R$ 900 com a história que permite refazer a conta.

```sh
python3 labs/architecture/financial.py ledger-projection --probe replay-events
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `replay-events`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "mutable_balance_without_history": 800
  },
  "after": {
    "replayed_balance": 900,
    "events": 3
  }
}
```

O vínculo é uma comparação executável de princípio. O probe exercita um requisito ou um contraexemplo relacionado a Append-Only Log; não implementa o padrão completo. Os eventos são fictícios. O WAL medido é do SQLite; ele não prova recovery PostgreSQL. Uma outbox, um log de auditoria ou uma projeção sozinha não transforma qualquer sistema em Event Sourcing.
