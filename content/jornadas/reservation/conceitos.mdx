# Conceitos: dois operadores disputam o mesmo recurso

Este mapa conecta os conceitos ao mesmo problema. Ana e Bruno são operadores fictícios que leem R$ 1.000 na versão 7. Ana registra um crédito de R$ 100 e chega à versão 8. Bruno ainda calcula seu débito de R$ 200 sobre a versão 7. Sem conferir a versão, ele grava R$ 800 e perde o crédito de Ana; ao reler o saldo, o resultado correto da intenção permitida é R$ 900.

Comece pela [jornada](/jornadas/reservation/), execute o [tutorial](/tutoriais/casos/reservation/) e use a [referência](/referencia/casos/reservation/) para consultar parâmetros. Para resolver sua própria tarefa, siga o [guia](/guias/casos/reservation/).

Cada entrada informa se você observa um mecanismo local ou se compara um princípio que uma implementação completa também precisaria atender. O segundo caso conserva a distância entre um modelo finito e um protocolo ou produto real.

<span id="compare-and-swap-cas" />

## Compare-and-Swap / CAS

CAS altera um valor somente se ele ainda coincide com o esperado.

No caso desta família, faça a seguinte observação: Compare a escrita baseada na versão 7 com a versão 8 já gravada. Releia e refaça 1.100 − 200 = R$ 900.

```sh
python3 labs/architecture/financial.py reservation --probe version-conflict
```

O código desta observação está em `labs/architecture/financial.py`. O identificador do probe é `version-conflict`.

Confira os valores do contrato antes e depois, e não apenas se as duas saídas são diferentes:

```json
{
  "before": {
    "balance": 800,
    "lost_credit": 100
  },
  "after": {
    "stale_rejected": true,
    "balance_after_reread": 900
  }
}
```

O vínculo é um mecanismo local executado. A conferência é um modelo determinístico local. Ela não prova um lock distribuído, um algoritmo lock-free ou wait-free, justiça de um RWLock ou atomicidade entre processos.

A [explicação do capítulo](/explicacoes/concurrency/) amplia a decisão, e a [entrada de referência](/referencia/catalogo/02-sistemas-distribuidos-e-consistencia/#g02-e029) descreve o conceito para consulta. A [jornada do caso](/jornadas/reservation/) permite continuar com o mesmo problema.

## Work Stealing

Um executor ocioso retira trabalho elegível de outra fila.

No caso desta família, faça a seguinte observação: Deixe B ocioso enquanto A tem duas tarefas. Faça B retirar uma tarefa elegível da outra ponta da fila de A e confira uma execução de cada tarefa.

python3 labs/architecture/financial.py reservation --probe idle-worker-steal

O código desta observação está em `labs/architecture/models_concurrency.py`. O identificador do probe é `idle-worker-steal`.
