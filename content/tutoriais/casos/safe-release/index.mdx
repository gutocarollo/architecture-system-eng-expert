# Experimente: a versão nova chega a quem ainda usa a antiga

Continue o mesmo caso: [volte ao caso](/jornadas/safe-release/); [entenda o mecanismo](/explicacoes/casos/safe-release/); [resolva a tarefa](/guias/casos/safe-release/); [consulte contratos e fontes](/referencia/casos/safe-release/).

Você concluirá uma experiência local e previsível. Você aprenderá a separar a compatibilidade do contrato, a população exposta e a volta para uma versão anterior. Este é um caso financeiro hipotético com participantes e dados fictícios. Uma corretora de maior porte, do setor em que atua a XP, é apenas o contexto de negócio. O texto não descreve um incidente nem uma arquitetura interna real da XP. A busca delimitada localizou candidatos da nossa stack, mas não estabeleceu um caso histórico completo para todos os conceitos desta família.

## 1. Prepare o ambiente isolado

Abra um terminal na raiz deste repositório de estudo. Confira Python 3.11 ou posterior. Para o caso de data, você também precisa de Node 20.9 ou posterior. Execute `npm ci --prefix labs/architecture` para instalar a versão do TypeScript fixada no lock dos laboratórios. O recibo desta autoria usou Python 3.14.8 e Node v26.8.1.

```sh
pwd
python3 --version
```

O diretório precisa conter `labs/architecture`. Prepare os laboratórios com o comando abaixo. Ele cria uma virtualenv local e instala o SDK OpenTelemetry fixado pelo lock; o caso de mTLS usa a CLI OpenSSL 3.x. Confira `openssl version`; o recibo desta versão usou OpenSSL 3.6.5.

```sh
python3 labs/architecture/setup_labs.py
```

Os programas trabalham em memória ou em uma pasta temporária criada pelo Python. Eles usam somente identidades e chaves sintéticas. A instalação baixa os pacotes do lock. As práticas não fazem requisições externas nem gravam nos sistemas de produção; mTLS usa pares de sockets locais sem abrir porta de escuta.

## 2. Reconheça a entrada que será repetida

Objeto antigo amount=1000, objeto novo amount_cents=100000, cem requisições numeradas e duas funções puras. Você repetirá a mesma entrada entre as condições comparadas; os eventos e relógios controlados eliminam a necessidade de acertar um intervalo manualmente.

## 3. Execute as duas condições

```sh
python3 labs/architecture/financial.py safe-release
```

O programa executa a condição anterior, executa a posterior e termina com `comparison=PASS` quando suas verificações passam. PASS neste roteiro significa que a falha ou diferença esperada apareceu antes e a garantia delimitada apareceu depois. A condição anterior deve mostrar o problema; portanto, observar seu sintoma é parte do resultado correto do exercício.

## 5. Examine a mudança

Abra `labs/architecture/financial.py` e procure a função `safe_release`. Localize a decisão que calcula before e a que calcula after. Compare a entrada e o recurso protegido. O modelo anterior e a proteção estão no mesmo arquivo para permitir repetir a comparação com segurança.

Esta família também possui propriedades específicas em `labs/architecture/models_ops.py`. O mapa de conceitos liga cada propriedade ao seu probe, às entradas e ao limite. Você pode abrir a função `observations` do módulo e procurar o identificador mostrado no comando.

Para repetir somente um probe, copie seu nome do campo `probe` e acrescente-o ao comando:

```sh
python3 labs/architecture/financial.py safe-release --probe expand-contract
```

## 7. Reinicie e conclua

Execute o mesmo comando outra vez. Cada processo começa com fixtures novas; as pastas SQLite temporárias são removidas pelo próprio programa. Não existe comando de limpeza contra banco, cache ou serviço externo.

Esta é uma simulação de contratos e rotas em memória. Não houve deploy, Kubernetes, GitOps ou Terraform. Desviar tráfego não desfaz dados incompatíveis já gravados.
