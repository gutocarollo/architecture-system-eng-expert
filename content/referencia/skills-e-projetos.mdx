# Skills e projetos de referência

Uma skill orienta o trabalho de um agente. Uma biblioteca ou framework fornece mecanismos para o programa. Uma aplicação de referência mostra esses mecanismos trabalhando juntos. O catálogo indica o papel de cada recurso, porque uma orientação bem escrita não implementa sozinha uma transação, uma fila ou uma eleição.

A [curadoria dos 310 conceitos](/referencia/curadoria/) é a referência atual por item. Ela liga cada conceito a SKILL.md público, código de biblioteca ou framework, aplicação selecionada, revisão e licença. Também conserva a medição mensal da página GitHub Trending de 15/10/2026, com o universo observado e os limites da comparação. As tabelas desta página preservam os snapshots históricos de descoberta de 14/10, sem substituir essa matriz.

Airbyte e outros projetos de código público podem ter condições source available nas revisões examinadas. A presença nesta descoberta não os classifica automaticamente como aplicação OSS. Para CDC, a matriz atual seleciona NiFi e mantém a licença ELv2 encontrada no Airbyte como motivo da substituição. As versões e licenças do código selecionado devem ser conferidas na entrada do conceito.

## Como interpretar a curadoria

As estrelas abaixo vieram de consultas à API oficial do GitHub em **14/10/2026, a partir de 17:12 UTC**. A ordem compara os repositórios consultados. Ela não constitui um ranking de todos os projetos de arquitetura nem uma série temporal de crescimento. O valor `pushed_at` informa a última atualização registrada pela API; ele não certifica qualidade, suporte ou uma release recente.

A consulta à página GitHub Trending daily encontrou doze repositórios, sem interseção com os sessenta da seleção. `K-Dense-AI/scientific-agent-skills` apareceu naquela página, mas seu foco científico não o torna automaticamente uma escolha para Outbox ou CQRS. Relatos no Reddit e no Hacker News foram usados como sinal de interesse, com a verificação técnica feita em documentação e código do próprio projeto.

Para escolher, confira o problema, a linguagem, a manutenção, a licença e o código do exemplo. O catálogo distingue uma aplicação didática (**REF**), um produto OSS e uma referência histórica. `NOASSERTION` é o resultado do campo de licença da API; consulte os arquivos de licença e a versão antes de decidir.

## O contrato de uma skill de padrão

O texto de origem propõe uma biblioteca em que o agente reconhece a dor e carrega a skill relevante. A estrutura abaixo descreve essa proposta; este curso não instalou nem criou um pack novo.

```text
architecture-skills/
  foundations/
    distributed-systems/
    consistency/
    ddd/
    messaging/
  patterns/
    transactional-outbox/
    saga/
    cqrs/
    cache-aside/
    distributed-lock/
  references/
    temporal/
    debezium/
    eventuate/
    etcd/
```

Cada `SKILL.md` precisa dizer quando o agente deve chegar ao recurso, quais fontes decidem a ação e como reconhecer a conclusão. Os catorze elementos propostos no texto têm os seguintes papéis:

| Elemento | Informação que deve registrar |
| --- | --- |
| `Problem` | A dor concreta que o mecanismo resolve. |
| `When to use` | As condições que justificam a escolha. |
| `When NOT to use` | As condições em que o custo supera o benefício ou a garantia é insuficiente. |
| `Failure modes` | As falhas, janelas de incerteza e formas de recuperação. |
| `Decision tree` | As perguntas e os critérios que levam à opção apropriada. |
| `Canonical implementation` | O contrato e o mecanismo comprovados na fonte escolhida. |
| `Preferred OSS libraries` | As bibliotecas verificadas e o papel de cada uma. |
| `Reference OSS implementations` | Os caminhos de aplicações que demonstram o padrão, com seu tipo de referência. |
| `Alternatives/trade-offs` | Os benefícios e os custos das alternativas relevantes. |
| `Testing strategy` | As propriedades e as falhas que a verificação deve distinguir. |
| `Observability` | Os sinais que mostram execução, atraso, erro e recuperação. |
| `Production checklist` | As pré-condições operacionais para o recorte autorizado. |
| `Anti-patterns` | As formas de uso que oferecem uma garantia falsa ou escondem uma falha. |
| `References` | As fontes, as versões e os localizadores usados. |

O mecanismo de roteamento evita carregar uma biblioteca inteira para uma decisão pequena. Por exemplo, a operação que precisa preservar uma intenção após o commit pode carregar a referência de Outbox e idempotência. Uma discussão sobre a apresentação do seletor Manual/Automático pode carregar as referências de MVC, MVP e MVVM. A seleção depende da pergunta e da garantia necessária.
